## 실행 루프

1. 기존 미커밋 변경·레퍼런스·현재 화면·장치 인터페이스를 확인한다.
2. gpt-6-astra 작업자가 모델/화면/엔진을 구현하고 실패 경로를 포함한 테스트를 실행한다.
3. 별도 리뷰 작업자가 실제 diff와 테스트를 읽고 안전·상태·통계·영속성·화면 불일치를 검토한다.
4. 중대 결함을 동일 구현 작업자에게 전달하고 수정 후 해당 검사와 전체 회귀 검사를 실행한다. 최대 3회 뒤 남은 결함을 숨기지 않는다.
5. Lead는 모델/과금 meta, result, 실제 diff를 확인하고 빌드·테스트를 직접 재실행한다.
6. Mac 실제 앱에서 정상/실패/복구/비교/재생 흐름을 조작하고 화면을 확인한다. Windows는 가능한 교차 빌드까지만 검증하며 실실행과 구분한다.
7. .review/control-upgrade/에 로그·화면·최종 수용표를 보관하고 결과/한계를 보고한다.

## 검증 명령

대상 저장소에서 PATH에 ~/.dotnet을 추가하고 DOTNET_CLI_HOME=$PWD/.dotnet-home, DOTNET_NOLOGO=1, DOTNET_CLI_TELEMETRY_OPTOUT=1을 설정한다.

- dotnet build -c Release --no-restore -v:q -m:1 /p:UseSharedCompilation=false
- dotnet test tests/Tests/Tests.csproj -c Release --no-build -v:q
- git diff --check

## 판정 규칙

테스트 기대값을 약화하거나 반송시간을 0으로 만들어 장애를 숨기지 않는다. 장치 상태가 불명확하면 안전 조건을 충족했다고 간주하지 않는다. 실제 장비의 품질/충돌 검증으로 주장하지 않는다. 비교 시뮬레이션은 현재 라이브 장치를 재사용하지 않는다. 사용자 데이터 삭제·발행·대량유료생성은 범위 밖이다. 새 3D 부품이 필요하면 기존 Higgsfield MCP 장면의 revision을 조회한 뒤 수정하고 렌더를 확인한다.
