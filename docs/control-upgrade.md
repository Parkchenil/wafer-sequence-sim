# 제어 관찰성·가상 장애 복구 수용 기록

확인일: 2026-10-13. 완료계약은 [verification-loop.md](verification-loop.md)이다. 실제 장비 안전 인증이나 물리 충돌·접촉 품질 검증이 아니다.

## 조작

Mac과 Windows의 오른쪽 **제어** 탭은 요청 인터락, 4PP 상세, 장애 상태와 복구 저널을 함께 표시한다. **실험** 탭에서 기준을 캡처하고 기존 레시피 편집기로 조건을 바꾼 뒤 비교한다. Mac 왼쪽의 제어/A·B 버튼으로도 탭을 연다. 재생 중에는 장비·장애 조작을 막고 기록된 스냅샷만 표시한다.

- 인터락은 요청 시의 조건·값·허용 기준·결과를 기록한다. XY는 Z 안전 높이·진공·EMO·반송 영역을 검사하고 Z 하강은 진공·XY 정지·EMO·반송 영역을 검사한다. FOUP↔얼라이너를 분리 반송 영역으로 가정한다. 척 접근은 원점·Z 안전 높이와 척/로봇 잠금 순서로 계측과 분리한다. 중단된 로봇은 수납으로 바꾸지 않으며 영역을 미확인으로 남긴다. 척 재석과 로봇 보유가 남아 있으면 새 로트로 덮어쓰지 못한다.
- 4PP는 접근→접촉 확인→안정화→샘플링→품질 판정→상승이다. 접촉 실패는 50 µm 상승 후 재접촉하며 `ContactMaxRetry`까지만 재시도한다. `ProbeSettleTime`은 ms, `QualityTolerancePct`는 반복 Rs의 표본 표준편차/평균 ×100(%), `QualityMinSamples`는 최소 반복 수, `QualityMaxRetry`는 별도 재측정 한도다. 품질 판정은 기존 레시피 호환을 위해 기본 비활성이며 비활성 결과는 실험에서 **품질 미판정**으로 표시한다. 활성화 시 최소 2개 이상을 요구하고 실제 반복 수가 최소값보다 작으면 거부한다. 접촉 재시도 소진과 품질 재측정 소진은 서로 다른 알람이다. 최종 불량은 완료/양품 수에 포함하지 않는다.
- 3D의 측정부 확대는 실제 축 높이, 접촉 참값과 마지막 관측값, 샘플 전압·편차·재시도/한도를 보여 준다. 관측값은 마지막 접촉 관측이며 상승 후 현재 참값과 다를 수 있다. Z 높이를 낮추면 품질이 좋아진다는 모델은 사용하지 않는다.
- 비교는 새 장치·새 엔진·독립 시계에서 실행하며 live 장치와 DB를 재사용하지 않는다. 기준의 wafer 수·site 좌표·seed를 고정한다. Z 상승, 이송 속도, 안정화, 재시도, 중첩 등 나머지 후보 레시피를 사용한다. 단일 실행 큐를 비운 뒤 가상 타이머를 진행하므로 overlap도 같은 조건의 로그/결과가 재현된다. 실적 WPH는 완료 장수 ×3600/로트 경과 초다. 상단의 예상 WPH(3600/평균 Tact)와 다르다. 불완료 실행의 WPH는 null이며 **— (불완료)**로 표시한다. 실패 사유와 부분 완료 수는 별도로 표시한다. 재시도율의 분모는 성공 사이트가 아니라 시도한 사이트다. 모듈별 시간 합은 중첩 때문에 로트 경과시간보다 클 수 있다. 취소·중복 실행 방지가 적용된다.

## 장애와 저장 범위

| 조작 | 실제 동작 | 제한·실패 처리 |
|---|---|---|
| 통신 단절 / 복원 | 진행 중 가상 명령은 종료 지점까지 완료하고 신규 의존 명령을 보류한다. 복원 후 축 정지·척 재석·로봇 보유·얼라이너 점유를 추적 정보와 대조한다 | 사용자 복구 대기는 기본 120 벽시계초이며 배속/즉시 모드와 무관하다. 50 ms마다 취소·EMO를 확인한다. 장치 정지 확인은 별도의 30 가상초 제한이다. 불일치는 차단한다. 미확인 상태에서는 복귀 Z 모션도 재발행하지 않는다. 중단 가능 |
| 센서 지연 / 정상 | 접촉 관측을 접촉 확인 시작부터 5 가상초 동안 지연한다. 물리 가상 참값을 바꾸지 않는다 | 레시피 접촉 제한시간을 넘으면 접촉 실패. 재시도마다 5초 지연이 다시 시작되므로 접촉 제한시간이 5초보다 짧으면 해제하지 않는 한 재시도를 소진한다. 정상 버튼은 진행 중 관측을 해제하며, 재석/진공 센서를 강제 참으로 만들지 않는다 |
| DB 실패 / 복구 | 실제 SQLite 쓰기 메서드에서 IO 실패를 발생시킨다. 측정 요약·실행 기록·로그는 파일을 `Flush(true)`한 뒤 재시도 대상으로 유지한다 | 비동기 큐는 레시피 용량, 미복구 저널은 256건/미확인 payload 128 MiB 한도이며 ACK를 포함한 과거 파일 크기는 제한에 포함하지 않는다. 저널 기록 자체가 실패하면 안전 정지 |

저널은 데이터 폴더의 `recovery.jsonl`이다. 기본 데이터 폴더는 OS LocalApplicationData의 `wafer-sequence-sim`이며 `WAFER_SIM_DATA` 환경변수로 별도 폴더를 지정할 수 있다. Mac/Windows가 같은 설정을 사용한다. 위치·미복구 건수·주입 상태를 제어 탭에 표시한다. `Journaled`는 해당 실행·해당 웨이퍼의 미확인 저장 건만 뜻하며 다른 웨이퍼의 대기 건수와 무관하다. 복구는 기본키 upsert와 영속 ACK로 반복 실행/재시작 후에도 중복 행을 만들지 않는다. 실행 최종 저장에는 자식 행을 보존하는 `IRunFinalizer`를 사용한다. 기존 SQLite 스키마나 사용자 데이터를 삭제하지 않았다. 기존 `SaveRunAsync` 교체 API의 동작은 호환을 위해 유지하되 운영 엔진/복구 경로는 이를 호출하지 않는다.

## 가정·남은 검토

- live의 일반 Instant 경로는 기존 스레드풀 기반 시계다. 엄격한 재현성은 A/B 실험의 단일 실행 큐 경로로 검증했다. 실시간 배속은 OS 타이머 해상도에 영향을 받는다.
- 일시정지는 **다음 단계 시작을 보류**한다. 진행 중 명령/안전 감시/가상 시간까지 동결하는 기능은 아니다. 실행 종료 시각은 고정된다.
- 통신 단절은 가상 명령 경계 장애이며 실제 케이블 단선이나 모션 컨트롤러 재연결 구현이 아니다. 센서 지연의 범위는 접촉 관측이다.
- **안전 회수**는 활성 로트/초기화가 없는 상태에서만 실행한다. 통신·EMO·접촉·도어·축 위치/원점/정지·재석·보유·원래 슬롯 점유를 대조한다. 중단 위치는 가상 로봇 내부에 보존된 경로가 있을 때만 인계면에서 이격·후퇴한다. 이후 Z 안전 높이, XY 원점, 진공 해제 센서를 확인하고 보유→얼라이너→척 순서로 원래 슬롯에 반환한다. 최종 수납 대조 후에만 다음 로트를 허용한다. 불량 통계와 기존 저장 자료는 보존하며 실제 스크랩이 아니다. **회수 중단**과 60 벽시계초 제한이 있고, 중단 시 현재 위치·소유권을 유지한다. 알 수 없는 상태는 자동 보정하지 않고 거부한다.
- 저널 active가 기본 8 MiB 이상이고 미확인 건이 0일 때 다음 저장/복구 경계에서 고유한 `recovery.jsonl.archive-<시각>-<UUID>.acked`로 원본 그대로 rename하고 새 active를 만든다. 보관 파일은 자동 삭제하지 않는다. 디스크 사용량은 보존 기간에 따라 계속 늘어나므로 별도 백업·보존 정책은 운영자가 결정한다. 디스크 고갈이나 저널 쓰기 실패는 안전 정지한다.
- 마지막 손상 줄은 원본을 `.tail-original` archive로 보존하고 유효 prefix만 복구한다. 완성되지 않은 마지막 기록은 성공 처리하지 않고 경고를 남긴다. 중간 손상은 저장/새 로트 시작을 차단하지만 앱은 열려 오류 위치를 표시한다. 교체 prefix를 먼저 flush하고 SHA-256 완료 표식을 flush한 뒤 원본 보관→교체 활성화 순서로 진행한다. 준비/두 rename 사이 중단과 ACK 유실을 재시작 테스트로 검증했다. 미완성 준비 파일도 보관한다. 프로세스 중단 복구와 키 기반 멱등성 범위이며 파일시스템 자체 손상·전원 장애의 하드웨어 내구성 인증은 아니다.
- 기존 revision 7 GLB 및 part mapping을 변경하지 않았다. SHA-256: `d7f3946efdde0a680ab93df905bd3164ea5758a9a0e3f7e5f04e277b0e851e8b`.
- 2026-10-13 Lead 최종 기술 수용 완료. 별도 Claude/Codex 리뷰 후 안전 회수·저널 복구 결함을 수정했고, Lead 추가 회귀에서 발견한 ACK 유실 재생 순서 문제도 수정했다. Lead가 최종 소스로 Release/Windows 교차 빌드(각 경고 0·오류 0), 전체 158개 테스트(실패 0·건너뜀 0)를 직접 실행했다. 실제 Mac 앱의 기준 캡처→비교에서 양쪽 64.64초·WPH 55.69와 기존 로트 상태/시간 보존을 확인했다. Windows 실제 실행은 미검증이다. 최종 근거는 `.review/control-upgrade/lead-acceptance.json`에 기록했다.

## 화면 근거

기존 실행 화면을 직접 열어 조작/지표→3D/타임라인→오른쪽 inspector 위계를 확인했다(2026-10-13). 기존 [3D 참고 기록](3d-reference-notes.md)과 `.review/transfer-detail/verification.json`의 revision 7 부품 대응을 그대로 사용했다. 새 정보는 오른쪽 두 탭에 배치하고 기존 색·타이포·카드·스크롤 패턴을 따랐다. 신규 geometry나 외부 생성물은 만들지 않았다. 원본 화면/조작 결과/실물 DB 검증은 로컬 검토 자료로만 보관한다.
